## 1. 项目定位与一句话介绍

### 1.1 一句话介绍
**MatrixFlow AI = 给中小企业雇一整支 AI 团队的操作系统。**
一个让用户可以创建、配置、管理、出售 AI 员工的 Web 平台，每个 AI �员工能接入知识库、工具、工作流、CRM、内容工厂、客服、数据看板和模板市场。

### 1.2 项目愿景
让任何不会写代码的中小企业老板，在 30 分钟内拥有一支由 AI 员工组成的内容、客服、销售、运营团队，并且这套团队可以被打包、出售、复用——最终形成一个「AI 员工 + 工作流 + 模板」的交易生态。

### 1.3 最重要原则
**不设计成"炫技但没人买"的平台。** 必须能卖钱、能上线、能演示、能扩展、能逐步开发。每一项功能都要回答：「这能让哪个真实用户掏钱？掏多少？」

### 1.4 商业切入点 [裁决]
**第一阶段只做"跨境电商 AI 运营团队"，不做全行业。**
MVP 第一版目标：用户上传一份商品资料，平台自动生成 15 类内容并一键入库/入工作流。

**MVP 最小可卖产品**：跨境电商 AI 内容工厂 + AI 员工工作台。
后续再扩展客服、CRM、工作流、模板市场。

## 2. 第一部分：产品战略

### 2.1 用户画像（5 类核心用户）

| 用户类型 | 典型角色 | 团队规模 | 月营收区间 | 核心诉求 | 付费意愿 |
|----------|----------|----------|------------|----------|----------|
| 跨境电商卖家 | Shopify/Amazon/TikTok Shop/独立站运营 | 1-10 人 | $1万-$100万 | 降低内容生产成本、多语言、多平台铺货 | 高，月付 $49-$499 |
| 内容创作者团队 | 小红书/TikTok/YouTube/MCN | 1-20 人 | $5千-$50万 | 批量内容、账号矩阵、品牌语气统一 | 中高，月付 $29-$299 |
| 中小企业老板 | 销售/客服/运营负责人 | 5-50 人 | $10万-$1000万 | 替代部分人工、降本、数据决策 | 高，月付 $99-$999 |
| AI 自动化服务商 | AI 顾问、自动化代理商 | 1-5 人 | 服务费制 | 卖模板、卖方案、做交付 | 极高，分成 + 高级套餐 |
| 教育/知识付费机构 | 课程方、社群方 | 5-30 人 | $5万-$500万 | 自动答疑、销售跟进、社群运营 | 中，月付 $99-$499 |

### 2.2 用户痛点（按类型）

**跨境电商卖家**
- 多平台铺货，每个平台文案规则不同，人工写不过来
- 多语言翻译质量差，机翻味重
- 广告文案 A/B 测试成本高
- 客服响应慢，时差问题严重
- 商品资料散落在 Excel，无统一管理

**内容创作者团队**
- 灵感枯竭，产出不稳定
- 多账号运营，语气难统一
- 短视频脚本写不出爆款
- 数据复盘靠人工

**中小企业老板**
- 想用 AI 但不会搭系统
- 市面上 AI 工具太散，不成体系
- 担心数据泄露
- 看不到 ROI

**AI 自动化服务商**
- 每个项目都要从零搭，无法复用
- 没有稳定的销售渠道
- 客户教育成本高

**教育机构**
- 答疑工作量巨大
- 销售线索跟进不及时
- 课程文案生产慢

### 2.3 目标市场
- **TAM**：全球中小企业 AI 自动化市场，2026 年预估 $200B+
- **SAM**：跨境电商 + 内容创作 + 中小企业 AI 工具，$30B
- **SOM（3 年）**：服务 10 万付费团队，ARR $50M

### 2.5 我们的差异化定位 [裁决]
**"AI 员工操作系统"** —— 不是工作流工具（n8n 类），不是内容工具（Jasper 类），不是 CRM（HubSpot 类），而是把三者封装成"可雇、可管、可卖"的 AI 员工。

三大护城河支点：
1. **AI 员工封装**：用户面对的是"员工"而非"节点/工具"，降低认知门槛
2. **跨境电商垂直**：先打透一个高付费意愿垂类，再横向扩展
3. **模板市场**：让服务商成为供给端，形成双边生态

### 2.6 为什么先做跨境电商
- 付费意愿最高（直接关乎收入）
- 痛点最明确（多平台、多语言、内容量大）
- 客单价承受力强（$49-$499/月是常规）
- 案例可复用（一个品类跑通，可卖给同品类）
- 现有工具都不好用（Shopify AI 太弱、Jasper 不懂电商）

### 2.7 为什么后期扩展到创作者经济和中小企业
- 创作者经济：与跨境电商同属"内容生产"链路，复用内容工厂 80%
- 中小企业：AI 员工概念天然适配"替代人工"诉求，复用 Agent + 工作流
- 扩展顺序：跨境电商 → 内容创作者 → 中小企业客服销售 → 教育机构 → AI 服务商生态

### 2.8 产品护城河
1. **数据护城河**：用户沉淀的知识库、品牌语气、历史内容 → 转移成本高
2. **网络护城河**：模板市场双边网络效应（服务商越多，买家越多，反之亦然）
3. **工作流护城河**：用户搭建的工作流越多，越离不开
4. **垂直护城河**：跨境电商行业 Prompt/模板/知识库的深度积累
5. **集成护城河**：与 Shopify/Amazon/TikTok 等平台的深度对接

### 2.9 商业模式
**四层收入结构：**
1. **SaaS 订阅**（主力）：按席位 + 用量阶梯计费
2. **用量计费**（弹性）：AI token、工作流执行次数、存储量超出套餐后按量
3. **市场分成**（生态）：模板市场交易抽佣 20%-30%
4. **企业定制**（高端）：私有部署、定制开发、SLA

### 2.11 冷启动策略
1. **种子用户**：找 50 个跨境电商卖家免费试用 3 个月，换案例
2. **内容营销**：每周 3 篇"跨境电商 AI 运营"实战文章
3. **社群**：建跨境电商 AI 运营微信群/Discord，提供免费工具
4. **KOL**：合作 10 个跨境电商 KOL，给专属分佣
5. **模板预埋**：上线即内置 50 个高质量跨境电商模板，开箱即用
6. **Product Hunt + 海外社区**：面向 Shopify/Amazon 卖家英文社区冷启

### 2.12 增长策略
1. **PLG**：免费版引流，用量到顶自动引导付费
2. **模板裂变**：用户买的模板可生成专属推广链接，分佣 10%
3. **集成生态**：上架 Shopify App Store、Zapier Integration、Chrome Extension
4. **合作伙伴**：与跨境支付、ERP、物流公司合作分销
5. **国际化**：英文版优先（跨境卖家本就需要英文界面）

### 2.13 风险分析

| 风险 | 等级 | 应对 |
|------|------|------|
| 大厂下场（Shopify/Amazon 自建 AI） | 高 | 走全平台、不绑定单一平台；做工作流和市场这种大厂不做的生态 |

| 数据合规（GDPR/中国数据出境） | 高 | 区域化部署（美国/欧盟/中国三套）；私有部署选项 |

| AI 输出安全（Prompt Injection） | 高 | §12 安全体系全套防护 |
| 同质化竞争 | 中 | 押注"AI 员工 + 市场"生态，不押注单点功能 |

## 4. 第三部分：技术架构

### 4.1 后端技术栈裁决 [裁决]
**最终采用：Node.js + NestJS + TypeScript + Prisma。**

裁决理由：
1. **全栈 TypeScript**：前后端同语言，类型可共享（DTO/Schema），团队成本最低
2. **NestJS 模块化**：契合 10 大业务模块的自然边界，DI + Module 利于大型项目
3. **Prisma**：TypeScript 优先 ORM，类型安全 + 迁移工具链成熟，配合 pgvector 有原生支持
4. **生态**：BullMQ（队列）、TanStack Query（前端）、流式 SSE 全链路 TS
5. **放弃 FastAPI 理由**：Python 在 AI 库上更强，但本项目的 AI 重头在"调用 + 编排"而非"训练"，TS 完全胜任；引入 Python 会带来双语言运维成本、类型断层、部署复杂度

> [补强] 预留 **Python Sidecar**（FastAPI 微服务）用于文档解析（Unstructured）、Embedding、未来可能的微调，通过内部 gRPC/HTTP 调用，不进主后端。

### 4.2 前端技术栈 [裁决]
- Next.js 14+ App Router（SSR + SEO + API Routes 兜底）
- React 18 + TypeScript
- Tailwind CSS + shadcn/ui（主题可控、可复制代码）
- React Flow（工作流编辑器）
- Zustand（轻量状态）+ TanStack Query（服务端状态）
- React Hook Form + Zod（表单与校验，与后端 DTO 共享 Zod schema）

### 4.3 数据与基础设施 [裁决]
- **PostgreSQL 16** + **pgvector**（主库 + 向量）
- **Redis 7**（缓存 + 队列 + 限流 + 会话）
- **BullMQ**（任务队列，基于 Redis）
- **MinIO**（S3 兼容对象存储，文件 + 导出代码）
- **ClickHouse [P1]**（用量/日志分析，量大后引入）

- **MVP**：Docker Compose 单机部署（前端 + 后端 + PG + Redis + MinIO）

### 6.1 API 总约定 [补强]
- **风格**：RESTful + SSE（流式输出）
- **版本**：`/api/v1/...`

## 11. 第十部分：模板资产生成 [裁决]

### 11.1 数量优化 [裁决]
原文数据量过大（100+100+100+50+5×1000=5450 项），实际生成会耗尽 token 且重复率高。优化为：

| 资产 | 原文数量 | 裁决数量 | 理由 |
|------|----------|----------|------|
| AI 员工模板 | 100 | **30**（覆盖 15 行业 × 2 角色） | 质量优先，避免重复 |
| 工作流模板 | 100 | **30** | 同上 |
| Prompt 模板 | 100 | **50**（覆盖 25 系统 Prompt × 2 变体） | 与 §9 对齐 |
| 行业解决方案 | 50 | **15**（每行业 1 个深度包） | 质量优先 |
| 商品测试数据 | 1000 | **100** + 生成器脚本 | 给脚本让用户自扩 |
| 客服对话测试数据 | 1000 | **50** + 生成器脚本 | 同上 |
| 社媒内容测试数据 | 1000 | **50** + 生成器脚本 | 同上 |
| CRM 线索测试数据 | 1000 | **50** + 生成器脚本 | 同上 |

> [补强] 提供 `scripts/generators/` 下的数据生成器脚本（Faker + 自定义规则），用户可一键生成任意数量测试数据，比静态 JSON 更实用。

## 13. 第十二部分：安全、合规与风控

### 13.1 安全体系 15 项（保留原文）
1. 用户认证安全（JWT + refresh rotation + 2FA [P1]）
2. API Key 安全（ hashed 存储、最小权限 scope、过期、IP 白名单 [P1]）
3. 多租户隔离（organization_id 行级 + RLS [P1] + 应用层 Guard）
4. 文件上传安全（类型校验、大小限制、病毒扫描 [P1]、MinIO 隔离 bucket）
5. RAG 数据泄露防护（租户隔离检索、引用不跨租户、脱敏）
6. Prompt Injection 防护（输入过滤、输出校验、沙箱工具）
7. Agent 工具权限控制（工具白名单、参数 schema、调用审批 [P1]）
8. 工作流执行沙箱（节点超时、资源限制、危险操作白名单）
9. 审计日志（所有写操作 + AI 调用 + 登录）
10. 内容安全审核（关键词 + 模型分类 [P1]）
11. 计费风控（异常用量告警、欠费限流、防刷）
12. 滥用检测（频率、内容模式、账号关联）
13. 模型输出过滤（敏感词、PII、违法内容）
14. 人工审批机制（高风险工作流节点、模板上架、退款）
15. 企业版私有部署方案（全套打包、License、SLA）

### 13.2 [补强] 合规
- **GDPR**：数据导出、删除请求、Cookie 同意、DPA
- **中国数据出境**：中国区域部署、用户数据不出境
- **SOC 2 [P2]**：日志、访问控制、加密
- **PCI DSS**：不存储信用卡，全走 Stripe [P1]

### 13.3 [补强] 实现层级
每项安全措施落到三个层级：
- **代码层**：Guard、拦截器、过滤器、参数校验
- **架构层**：网络隔离、最小权限、加密传输/存储
- **运维层**：监控、告警、审计、应急响应
