# MatrixFlow AI 界面设计系统

本规范用于保持公开页面、认证流程和工作台的一致性。设计参考 Apple Human Interface Guidelines 的清晰层级、克制材质和目的性动效，但不复制 Apple 的资产、组件外观或品牌表达。

## 原则

1. **内容优先**：颜色、模糊和动画只用于表达层级、状态或交互，不与核心任务竞争。
2. **层级清晰**：主要标题、正文、辅助信息和元数据使用固定字号阶梯，不通过堆叠多种字体制造差异。
3. **材质克制**：半透明材质用于导航、浮层和重要卡片；高密度文字区域使用更不透明的表面保证对比度。
4. **反馈直接**：悬停、按下、加载和切页反馈短而稳定；结构网格和低频扫光只用于建立空间感，不与内容争夺注意力。
5. **三语言同构**：简体中文、繁体中文和英文使用相同信息层级；窄屏允许换行，不允许裁切核心文案。

## 设计令牌

- 字体：优先系统字体。英文和数字使用系统 UI 字体；中文依次使用 MiSans、HarmonyOS Sans SC、PingFang SC 和 Microsoft YaHei UI 等本机字体。
- 正文：15–16px；普通辅助文案 13px；12px 只用于三级元数据，不再使用低于 12px 的可见文本。
- 标题：使用 `font-display`，Semibold 为主；避免 Ultralight、Thin 和大面积全粗体。
- 品牌色：`--primary` 只用于主操作、选中态和重要状态，不作为大面积页面底色。
- 圆角：控件以 12–16px 为主，卡片以 20–24px 为主，胶囊只用于短状态和主要 CTA。
- 表面：优先 `surface-card`、`interactive-card`、`panel-card` 和 `status-pill`，不要在业务页面重复拼装阴影和边框。

## 布局与组件

- 公开 Header 高度为 60px；移动端交互目标保持至少 44px，并在 320px 宽度内隐藏次要导航。
- 认证页面桌面端采用信息区和任务区双栏；移动端只保留任务所需内容，返回与语言控件固定在安全边距内。
- 工作台 Sidebar 只显示单层导航标签；路由说明放在 Topbar，避免同一信息重复出现。
- 表单统一使用共享 `Input`、`Select`、`Textarea`、`Label` 和 `Button`，不得在页面内复制焦点环或禁用态。
- 列表工具、空状态、错误状态、分页和确认对话框使用 `components/ui` 内的共享实现。

## 动效与背景

- 背景由低对比 56–96px 结构网格、缓慢环境光晕和带长停顿的低频扫光共同构成；网格必须渐隐，扫光不得覆盖文字或形成持续闪烁。
- 桌面端扫光周期不短于 26 秒，移动端、高对比度和 `prefers-reduced-motion` 环境不渲染扫光。
- 控件反馈使用 200–300ms 的缓出曲线；按下可轻微缩放，触控设备不保留悬停位移。
- 页面切换以短淡入和顶部进度反馈为主，不使用大幅水平或纵深转场。
- `prefers-reduced-motion` 下关闭非必要动效；`prefers-reduced-transparency` 下使用不透明表面。

## 可访问性与验收

- 所有交互必须有可见键盘焦点，图标按钮必须有可读名称。
- 状态不能只依靠颜色表达；错误、成功、警告和不可用状态同时提供文字或图标。
- 每次发布前运行 `pnpm verify` 和 `pnpm test:e2e -- --workers=1`。
- 浏览器回归至少覆盖 1440×900、390×844 和 320×800，并检查首页、登录、注册、定价及已登录工作台。
- 三种语言均需通过 SSR 语言、横向溢出和 Axe 严重级别可访问性检查。
