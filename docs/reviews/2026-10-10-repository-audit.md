## 验证

本地环境为 Node.js 26.10.0、pnpm 11.25.0；CI 仍使用仓库固定的 Node.js 22.14.0。

- `pnpm verify`：格式、schema、i18n、类型、lint、共享包/前端/脚本单测、生产构建、云函数语法与单测。
- 单元和脚本测试：共享包 11、前端 20、脚本 12、云函数 87，共 130 项。
- Chromium：原有 12 项全部通过，覆盖三语首屏与持久化、登录边界、恢复链接清理、320/390px 布局、触摸目标、动画策略和 WCAG 检查；另补充 Cookie 优先于旧存储、存储被隐私设置禁用的 2 项回归，均通过。
- 本地 `next start` 的生产页面巡检：6 个公开页面和 3 种语言，共 9 次检查通过，包含 canonical 与安全响应头。
- `pnpm audit --prod --audit-level=high`：无已知漏洞。
- `npm audit --omit=dev --audit-level=high`：无高危/严重漏洞；仍有 Mammoth → argparse → sprintf-js 链的 3 项中危告警。应用调用 Mammoth 的 `lib/index.js`，argparse 位于其命令行入口；审计建议降级至 Mammoth 0.3.29，未采纳破坏性降级。
- 线上巡检：本机 Node fetch 与 curl 均连接超时，无法确认当前线上状态；既有 GitHub 日志明确显示首页三语文案不匹配导致巡检失败。

## 上线条件与后续重点

1. GitHub 仓库 Secrets 列表当前为空。需要配置短期 `MATRIXFLOW_DEPLOY_KEY`、专用 `MATRIXFLOW_TEST_EMAIL` 和 `MATRIXFLOW_TEST_PASSWORD` 后，才能部署及执行真实账户/Provider 验收。凭据应只保存在供应商 Secret 存储中。
2. Function 必须配置真实 Provider、API Key pepper 和 Worker secret，随后验证活动部署、租户边界、AI 调用、异步任务及清理流程。本地非严格 readiness 的告警来自缺少这些外部配置。
3. 发布后检查历史 `idempotency_keys` 中 API Key 创建的响应记录；旧版可能保存过明文密钥。本轮只防止新记录继续写入明文，未访问或清理生产数据。需按既有密钥暴露情况制定清理/撤销计划。
4. 幂等请求指纹增加了身份与权限，因此旧记录在保留窗口内重试可能返回 IDEMPOTENCY_CONFLICT；不要盲目更换键重试未知结果，先核实操作是否已经完成。
5. 数据删除仍是逐表操作，活跃任务检查不构成跨表锁。执行删除期间应停止新写入；完整并发删除需要组织级停写状态与恢复流程。
6. 付费启用前，应强化计费事件的原子占用、乱序事件处理和跨表失败恢复。现有签名及唯一 eventId 不等于整个订阅/发票/交易更新事务。
7. 继续跟踪没有兼容补丁的 sprintf-js 与构建工具公告；生产依赖补丁依据 [Next.js 官方公告](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4) 及包管理器审计结果。

本轮未修改 Appwrite schema，未向生产发布，也未写入或删除远端业务数据。
