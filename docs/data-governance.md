# 数据治理与恢复边界

## 数据分类

| 类别        | 示例                                | 默认处理                                                    |
| ----------- | ----------------------------------- | ----------------------------------------------------------- |
| 账户/组织   | Appwrite 用户、Team、成员关系       | Appwrite Auth/Teams 管理，删除时校验管理员与精确确认        |
| 业务内容    | Agent、CRM、工作流、知识文档        | Team ID 隔离，普通行只读权限，写入统一由 Function 执行      |
| AI 运行数据 | Prompt 摘要、输出、Token、成本      | 记录用途和 request ID；Provider 密钥永不落库                |
| 安全审计    | `audit_logs`                        | Function-only，按安全保留策略留存                           |
| 计费证据    | 订阅、发票、支付、退款、拒付事件    | HMAC 校验、事件 ID 幂等，按财务保留策略留存                 |
| 凭据        | API Key、Provider Key、连接器 Token | API Key 仅保存哈希；Provider/连接器密钥仅存 Appwrite Secret |

## 导出与删除

`GET /account/export` 返回带版本号的 JSON 清单，包含组织行数据和文件元数据，不直接包含二进制文件。导出会递归脱敏名称包含 `key`、`secret`、`token`、`password`、`authorization` 或 `cookie` 的字段，并限制 5 MiB，防止一次请求拖垮 Function。

`DELETE /account` 是显式确认后的逐表删除流程：先删除知识文件，再按资源归属删除行。Appwrite TablesDB 不提供跨表事务，因此接口返回每张表的删除数量，失败后可以安全重试。安全审计、订阅、计费事件、发票和交易记录不会被静默删除，必须由独立保留策略处理，以保留退款、拒付、税务和安全事件调查所需的证据。

## 备份与恢复要求

- Appwrite 数据库、Storage、`background_jobs`、审计和计费表必须纳入备份。
- 生产备份至少保留 30 天，访问最小化并启用加密；具体保留时间以组织合规要求为准。
- 每季度恢复到隔离项目，核对租户边界、关键关系、文件可读性和脱敏导出；恢复环境禁止真实 Provider、邮件、Webhook 与支付回调。
- 恢复后先将异步任务设为暂停，避免重复执行；确认幂等键、计费事件和 API Key 撤销状态后再放流量。
- 破坏性 Schema 变更必须有备份 ID、恢复演练记录、迁移脚本和回滚负责人。
